## 회차 기록

### 지운 회차 (보존 규칙을 정하기 전)

| 회차 | 사유 |
|---|---|
| ② 점검 r0 (측정 모드 · S50 · 1일 · 저장, 1회째) | 원천 EntityManagerFactory 의 빈 이름이 JPA 자동 구성이 찾는 `entityManagerFactory` 와 달라 앱 기동 실패(health timeout). 결과 파일을 지웠다 |
| ② 점검 r0 (측정 모드 · S50 · 1일 · 저장, 2회째) | 하네스 점검 성공 회차(72,050행, 중복 0 · 누락 0). 체크포인트 c2b · c3a 를 넣기 전이라 지웠다 |

이후 무효 회차는 `reports/<질문>/invalid/` 로 옮기고 그 폴더 README 에 사유를 적는다.

### ② 상한 모드 02:10 ~ 09:52 의 공백 (회차 시간 상한을 두기 전)

| 구간 | 멈춘 회차 · 프로세스 상태 |
|---|---|
| 02:17 ~ 03:45 | A · S896 · 7일 · 256MB 회차. 앱은 첫 응답을 기다리고(GPU 조회 로그 없음, 컨테이너 메모리 약 245MiB), VM 안 Prometheus 가 쿼리당 약 300MB 응답을 만드는 동안 VM 가용 메모리 16MB · 부하 평균 60 으로 VM 전체가 멈춤. 03:45 에 앱 컨테이너를 죽이고 Prometheus 를 재시작해 회복. 이 회차는 `reports/q2/invalid/` |
| 03:49 ~ 05:49 | 다음 회차(짧은 값 S224 · 1일 · 256MB)가 초기화 단계(DB 명령)에서 멈춤. VM 안 Docker 데몬은 정상이었고, 호스트에서 VM 으로 가는 Rancher Desktop 의 소켓 · 포트 전달이 응답하지 않았다. 일괄 스크립트가 백그라운드 상한 2시간에 닿아 중단. 빈 결과 폴더는 `reports/q2/invalid/` |
| 05:49 ~ 09:52 | 회차 없음. 실행 권한 승인 대기(사용자 확인). 그 뒤 랩 전용 ssh 터널(`scripts/tunnel.sh`)로 경로를 복구해 09:52 에 다시 시작 |

공백 약 7.7시간 가운데 앞의 약 3.5시간은 위 두 줄의 VM 정지 · 전달 끊김(무효 회차 2개로 보존), 뒤의 약 4시간은 권한 승인 대기다. 측정값에는 영향이 없다(멈춘 두 회차는 판정에 쓰지 않는다).

이후 모든 회차는 `scripts/with-deadline.sh` 로 시간 상한을 건다. 저장 없는 회차는 20분, 저장 있는 회차는 예상 소요(90초 + 행 수 ÷ 2,500행/초)의 3배(최대 7,000초)다. 상한에 닿으면 앱 · 컨테이너를 정리하고 그 회차를 「시간 초과」로 남긴다.
